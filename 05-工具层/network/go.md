## 一、Goroutine & GMP 调度模型

### 核心概念

1. **Goroutine**：Go 实现的**轻量级协程**，区别于操作系统原生线程：
   - 初始栈空间极小（几KB），栈可动态伸缩；OS 线程栈固定且较大
   - 由 Go 运行时调度，而非操作系统内核，切换开销远小于线程
2. **GMP**：Go 调度三大核心组件（选择题必考三者定义+职责）
   - **G(Goroutine)**：代表一个待执行的协程，存储协程运行状态、栈、任务逻辑
   - **M(Machine)**：操作系统内核线程，真正负责执行代码，M 必须绑定 P 才能运行 G
   - **P(Processor)**：逻辑处理器，持有运行所需上下文、本地队列、调度资源，决定 M 能执行哪些 G

### 选择题高频考点

1. 调度规则：P 的数量默认等于 CPU 核心数（`GOMAXPROCS`），控制**并行度**
2. 单个 M 同一时间只能运行一个 G；一个 P 同一时间也只会绑定一个 M
3. Goroutine 是**用户态**调度，切换不触发内核态，这是“轻量”的核心原因

### ⚠️ 经典错误选项（直接排除）

- 错误：Goroutine 就是操作系统线程
- 错误：M 可以脱离 P 直接执行 G
- 错误：P 的数量越多，程序执行效率一定越高

## 二、Channel 通道

### 核心分类 & 阻塞规则（选择题最高频考点：判断是否阻塞、考点：判断是否阻塞、是否 panic）

Channel 用于 Goroutine 间通信，分为**无缓冲 Channel**、**有缓冲 Channel**。

#### 1. 无缓冲 Channel（长度为 0）

- 发送操作：**必须有协程同时准备接收**，否则发送方阻塞
- 接收操作：**必须有协程同时准备发送**，否则接收方阻塞
- 本质：同步通信，收发双方一一配对

#### 2. 有缓冲 Channel（容量 N > 0）

- 缓冲区**未满**：发送操作不会阻塞
- 缓冲区**已满**：后续发送操作阻塞
- 缓冲区**非空**：接收操作不会阻塞
- 缓冲区**为空**：接收操作阻塞

#### 3. Channel 关闭规则（必考正误判断）

1. **向已关闭的 Channel 发送数据 → 直接 panic**（高频坑）
2. **从已关闭的 Channel 接收数据**：
   - 缓冲区有值：正常取出数据
   - 缓冲区无值：返回对应类型**零值**，且 `ok=false`
3. 重复关闭同一个 Channel → panic
4. 使用 `for range` 遍历 Channel：通道关闭后，循环会正常退出，不会阻塞

### ⚠️ 经典错误选项

- 错误：关闭 Channel 后，接收数据一定会 panic
- 错误：有缓冲 Channel 满了之后，接收数据会阻塞
- 错误：可以多次关闭同一个 Channel

## 三、Slice 切片

### 核心基础

Slice 是**底层数组的引用**，属于引用类型，结构包含：**指针(指向底层数组)、长度(len)、容量(cap)**。

### 选择题高频考点

#### 1. 扩容规则（固定考点）

- 当容量 < 1024：扩容时**容量直接翻倍**
- 当容量 ≥ 1024：扩容时**每次增长原容量的 1/4（1.25倍）**
- 数组重新分配 = 新申请底层内存 + 数据复制 + ptr 更新

#### 2. 引用共享问题（易错多选）

1. 多个切片**截取自同一个底层数组**时，会共享数组元素，修改其中一个，其余切片同步受影响
2. 切片截取 `s[a:b:c]`：
   - 长度 = b-a，容量 = c-a
   - 截取操作**不会缩小原切片容量**（左不缩、右限制）

#### 3. nil 切片 vs 空切片（必考辨析题）

| 类型                   | len | cap | 底层数组       |
| -------------------- | --- | --- | ---------- |
| nil 切片 `var s []int` | 0   | 0   | 无底层数组      |
| 空切片 `s := []int{}`   | 0   | 0   | 有底层数组（空数组） |

- 二者**长度、容量都为0**，但底层数组不同；做 `==` 判断时：`nil切片 != 空切片`

### ⚠️ 经典错误选项

- 错误：切片是值类型，拷贝后互不影响
- 错误：切片截取后，容量一定会变小
- 错误：nil 切片和空切片完全等价

## 四、Map 字典

### 选择题核心考点（全是正误判断题）

1. **并发不安全（重中之重）**
   - 多个 Goroutine **同时读写 Map（读+写/写+写）**，不加同步措施 → 直接触发运行时 panic
   - 仅多协程**并发读**，不会报错
2. nil Map 特性
   - `var m map[string]int` 为 nil Map
   - 从 nil Map **读取数据**：正常执行，返回值类型零值，不 panic
   - 向 nil Map **写入数据**：直接 panic（高频坑）
3. 遍历特性
   - Map 底层是哈希表，**遍历顺序每次都不固定**，不存在有序遍历
4. Key 限制
   - Map 的 key 必须是**可比较类型**；切片、Map、函数 不能作为 key

### ⚠️ 经典错误选项

- 错误：Go 的 Map 支持并发读写，无需加锁
- 错误：nil Map 可以正常写入键值对
- 错误：Map 遍历顺序和插入顺序一致

## 五、defer 延迟函数

### 核心规则（执行顺序+时序，选择题必考）

1. **执行顺序**
   多个 `defer` 按照\*\*后进先出（栈顺序）\*\*执行：先声明的 defer 后执行，后声明的先执行。
2. **与 return 的执行时序（超级高频）**
   return 语句拆分为两步：
   ① 给返回值赋值 → ② 真正返回
   ✅ defer 函数**执行在 ① 和 ② 中间**，可以修改已赋值的返回值。
3. 变量捕获规则
   - defer 捕获外部变量为**值传递**：定义 defer 时就拷贝变量当前值，后续变量修改不影响 defer 内部
   - 循环中使用 defer 是经典错题场景。
4. panic 与 defer
   - 函数触发 panic 后，**已注册的 defer 依然会按顺序执行**
   - `recover()` 函数**只能在 defer 函数内部调用**才生效，用于捕获 panic
   - 未 recover 的 panic = 程序崩溃 （无论哪个协程）

### ⚠️ 经典错误选项

- 错误：defer 按照代码书写顺序依次执行
- 错误：return 执行完毕后，才会执行 defer
- 错误：recover() 可以在普通代码行中捕获 panic

## 六、Interface 接口

### 1️⃣ 基本概念

**接口（interface）** 是 Go 的一种**抽象类型**，定义了一组方法但不实现方法。

- **核心作用**：描述**行为**，而不是数据
- **实现方式**：**隐式实现**，无需 `implements` 关键字（与 Java 对比，必考）
- **实现条件**：类型的方法集**完全匹配**接口的所有方法

```go
type Speaker interface {
    Speak() string
}

type Person struct{}

func (p Person) Speak() string {
    return "hello"
}

var s Speaker
s = Person{} // ✅ 隐式实现，无需声明 implements
fmt.Println(s.Speak()) // hello
```

***

### 2️⃣ 接口变量的本质

接口变量是一个**二元组**：**(动态类型 + 动态值)**

```go
var i interface{} // 空接口
i = 42            // 动态类型=int, 动态值=42
i = "hello"       // 动态类型=string, 动态值="hello"
```

#### ⭐ nil 判断规则（经典压轴题）

- **只有动态类型、动态值全部为 nil** 时，接口变量才等于 `nil`
- **高频陷阱**：类型不为 nil、值为 nil → 接口变量 **≠ nil**

```go
var p *Person = nil
var i interface{} = p  // 动态类型=*Person, 动态值=nil

fmt.Println(i == nil)  // ❌ false（类型不为 nil）
fmt.Println(p == nil)  // ✅ true（指针本身为 nil）
```

***

### 3️⃣ 空接口 interface{}

**万能类型**，可以存储**任何类型的值**

```go
func Print(v interface{}) {
    fmt.Println(v)
}
Print(123)      // ✅
Print("hello")  // ✅
Print(nil)      // ✅
```

**常见用途**：

- 通用函数参数
- 存储不确定类型的数据
- `map[string]interface{}` 存储任意 JSON 数据

***

### 4️⃣ 类型断言（Type Assertion）

从接口变量**取回具体类型的值**

```go
var i interface{} = "hello"

s := i.(string)        // ✅ 成功，s="hello"
n := i.(int)           // ❌ panic（断言失败）
n, ok := i.(int)       // ✅ 安全方式，ok=false, n=0
```

#### 笔试常考点

1. **带** **`ok`**：断言失败 → `ok=false`，**不 panic**
2. **不带** **`ok`**：断言失败 → **直接 panic**
3. **只能断言为实际存储的具体类型**或**目标接口**

***

### 5️⃣ 接口方法调用（动态绑定）

接口调用方法时，**运行时动态绑定**到底层实际类型

```go
func SpeakSomething(s Speaker) {
    fmt.Println(s.Speak())  // 动态绑定
}

SpeakSomething(Person{})  // 调用 Person.Speak()
```

**多态本质**：同一接口变量，根据实际类型执行不同方法

***

### 6️⃣ 高频易错点总结表

| 考点          | 易错理解              | 正确理解                       |
| ----------- | ----------------- | -------------------------- |
| 实现接口        | 必须显式 `implements` | **方法集匹配即可**，隐式实现           |
| 接口变量是否为 nil | 值为 nil 就等于 nil    | **类型 + 值全为 nil** 才等于 nil   |
| 空接口         | 只能存储某些类型          | **可以存储任何类型**               |
| 类型断言        | 失败自动返回零值          | 失败会 **panic**，安全写法 `v, ok` |
| 接口方法调用      | 静态绑定              | **动态绑定**（多态）               |

***

### ⚠️ 经典错误选项（直接排除）

- ❌ 错误：只要接口内部值是 nil，接口变量就等于 nil
- ❌ 错误：类型断言失败后，程序不会报错
- ❌ 错误：Go 中类型实现接口必须显式声明
- ❌ 错误：接口变量存储指针为 nil 时，接口变量等于 nil
- ❌ 错误：类型断言可以断言为任意类型

***

### 💡 记忆口诀

> **"接口只是行为签名，变量存储类型和值，**
> **空接口可以存任何东西，断言安全写 (v, ok)，方法调用是动态的。"**

***

### 🎯 笔试速记关键词

1. **隐式实现** → 方法集匹配即可
2. **二元组** → 动态类型 + 动态值
3. **nil 判断** → 类型值全 nil 才 nil
4. **类型断言** → 失败 panic，安全用 ok
5. **动态绑定** → 运行时多态

***

## 七、Context 上下文

### 核心作用

在**父子 Goroutine** 之间传递：取消信号、截止时间、请求元数据，统一管理协程生命周期。

原理流程： 超时后，自动调用 cancel方法， 然后 会从 耗时任务中退出 出来，然后可以捕获到`ctx.Err()，从而返回错误原因是超时`

defer cancel（）的原因是 ，避免 任务正常完成，退出函数，这个context无人处理 ，兜底保证 这个context被关闭，回收资源

### 选择题高频规则

1. **传递原则**：Context 必须**自上而下层层传递**（父 → 子协程），禁止反向传递、全局存储 Context。
2. **父子关联**：父 Context 触发取消/超时，**所有派生的子 Context 都会一并取消**。
3. 常用衍生函数区分：
   - `WithCancel`：手动触发取消
   - `WithTimeout/WithDeadline`：超时/到点自动取消
   - `WithValue`：仅用于传递**请求域只读数据**，不建议传递函数、大对象、控制逻辑
4. `ctx.Done()`：返回一个只读通道，Context 取消/超时后，该通道会被关闭，用于协程监听退出信号。   

这里其实就是实现 超时控制，优雅退出的核心。

例如：网络操作内部传入了 ctx，实际上 一个网络内部就有一个一直监听这个的 代码，监听到消息后就终止网络操作，退出，然后后续的代码就捕获到err了

1. `ctx.Err()`：Context 取消后，返回具体的取消原因。

### ⚠️ 经典错误选项

- 错误：子 Context 取消后，会影响父 Context
- 错误：可以将 Context 定义为全局变量跨协程使用
- 错误：WithValue 可以用来传递业务函数、锁等控制类对象

# 📝 选择题速记清单（考前快速复盘）

1. 协程：Goroutine=轻量级协程，调度依赖 GMP，切换开销远小于线程
2. Channel：无缓冲必须配对收发；有缓冲看缓冲区；关通道后发数据必 panic
3. Slice：引用类型、共享底层数组；扩容 <1024翻倍，≥1024增1/4；nil切片≠空切片
4. Map：**并发读写不安全**；nil map 可读不可写；遍历无序
5. defer：后进先出；执行在 return 赋值之后、返回之前；recover 仅 defer 内生效
6. Interface：隐式实现；接口nil要求**类型+值全nil**；类型断言失败分两种结果
7. Context：自上而下传递；父取消子全取消；仅用 WithValue 传请求数据
