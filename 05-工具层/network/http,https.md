# HTTP & HTTPS 笔试通用背诵笔记（精简版，直接背诵）

## 一、核心属性总对比（表格速记，笔试高频考点）

| 对比维度 | HTTP               | HTTPS                  |
| ---- | ------------------ | ---------------------- |
| 安全性  | **明文传输**，数据易被窃听/篡改 | **加密传输**，防窃听、防篡改、身份验证  |
| 默认端口 | 80                 | 443                    |
| 协议层级 | 应用层                | 应用层 + TLS/SSL 加密层      |
| 连接建立 | TCP 三次握手后即可通信      | TCP 三次握手 + TLS 握手后才能通信 |
| 性能   | 较快（无加密开销）          | 稍慢（加密解密开销）             |
| 证书要求 | 无需证书               | 需要服务器配置 SSL/TLS 证书     |
| 适用场景 | 内部系统、对安全要求低的场景     | 登录、支付、所有对外公开的网站        |

## 二、分模块精细化背诵要点

### （一）HTTP 必背要点

1. **请求方法（8种核心，笔试常考）**
   - `GET`：获取资源，**幂等、无副作用**，参数在 URL 中（有长度限制）
   - `POST`：提交数据，**非幂等**，参数在 Body 中，用于创建资源
   - `PUT`：更新资源（全量替换），**幂等**
   - `DELETE`：删除资源，**幂等**
   - `PATCH`：局部更新资源
   - `HEAD`：获取响应头（不返回 Body）
   - `OPTIONS`：预检请求，用于 CORS
   - `TRACE/CONNECT`：调试/代理隧道（了解即可）
2. **状态码（按类别背诵，笔试必考）**
   - **2xx 成功**
     - `200 OK`：请求成功
     - `201 Created`：资源创建成功
     - `204 No Content`：成功但无返回内容
   - **3xx 重定向**
     - `301 Moved Permanently`：永久重定向（SEO 权重转移）
     - `302 Found`：临时重定向
     - `304 Not Modified`：协商缓存命中，使用本地缓存
   - **4xx 客户端错误**
     - `400 Bad Request`：请求参数错误
     - `401 Unauthorized`：未认证（需要登录）
     - `403 Forbidden`：无权限访问
     - `404 Not Found`：资源不存在
   - **5xx 服务器错误**
     - `500 Internal Server Error`：服务器内部错误
     - `502 Bad Gateway`：网关错误（上游服务器无响应）
     - `503 Service Unavailable`：服务暂时不可用
3. **核心特性（易错点）**
   - **无状态**：服务器不保存客户端上下文，每次请求独立
   - **明文传输**：数据不加密，易被中间人攻击
   - **请求-响应模式**：一个请求对应一个响应
4. **常见请求头/响应头（笔试高频）**
   - `Content-Type`：数据格式（`application/json`、`text/html` 等）
   - `Cache-Control`：缓存控制（`no-cache`、`max-age=3600` 等）
   - `Set-Cookie`：服务器设置 Cookie
   - `Authorization`：携带认证信息（Token）
   - `Accept-Encoding`：支持的压缩格式（gzip、brotli）

### （二）HTTPS 必背要点

1. **三大安全性保障（笔试超级高频）  CIA三元组   ，核心就是为了实现这三个，后续所有 行为都是为了这三点**
   - **加密（Confidentiality）**：TLS 加密传输，防止中间人窃听
   - **完整性（Integrity）**：校验数据是否被篡改
   - **身份验证（Authentication）**：服务器证书验证身份，防止假冒网站
2. **TLS 握手流程（四次握手，笔试高频）**
   > **前提**：TLS 1.2 四次握手是在 **TCP 三次握手建立连接之后** 执行的，目的是协商加密规则、验证服务器身份、协商出对称密钥，为后续 HTTP 数据加密铺路。
   ***
   **密钥生成三要素（重要！）**

   最终的对称会话密钥由以下三个要素共同生成：
   | 要素         | 来源               | 作用            |
   | ---------- | ---------------- | ------------- |
   | **客户端随机数** | 第1次握手，客户端生成并发送   | 确保客户端参与密钥生成   |
   | **服务端随机数** | 第2次握手，服务端生成并发送   | 确保服务端参与密钥生成   |
   | **预主密钥**   | 第4次握手，客户端生成并加密传输 | 密钥的核心种子，防止被截获 |
   > 三个要素缺一不可，任何一方无法单独决定密钥，且每次连接都不同。
   ***
   ### TLS 1.2 四次握手详解
   **第一次握手（客户端 → 服务端：Client Hello）**
   - 客户端生成 **客户端随机数**
   - 携带：支持的 TLS 版本、加密算法套件、**客户端随机数**
   - 作用：告诉服务端 "我支持哪些加密方式，这是我的随机数"
   **第二次握手（服务端 → 客户端：Server Hello）**
   - 服务端生成 **服务端随机数**
   - 返回：选定的 TLS 版本、加密方案、**服务端随机数**
   - 作用：敲定后续通信的加密规则
   **第三次握手（服务端 → 客户端：数字证书 + Server Hello Done）**
   - 服务端下发 **数字证书**（内含服务器公钥）
   - 客户端校验证书：合法性、域名匹配、CA 可信
   - 作用：完成 **身份认证**，确认服务端身份，防止钓鱼网站
   **第四次握手（客户端 → 服务端：发送密钥 + 加密切换指令）**
   - **步骤 1：生成预主密钥**
     - 客户端随机生成 **预主密钥**（48 字节的随机数）
   - **步骤 2：安全传输预主密钥**
     - 用证书中的**服务器公钥**加密预主密钥
     - 发送给服务端，只有服务端私钥能解密
   - **步骤 3：双方分别生成会话密钥**
     - 客户端：`会话密钥 = PRF(客户端随机数，服务端随机数，预主密钥)`
     - 服务端：`会话密钥 = PRF(客户端随机数，服务端随机数，预主密钥)`
     - 双方计算出的会话密钥**完全相同**
   - **步骤 4：确认密钥协商成功**
     - 双方互发 **Finished** 报文，用会话密钥加密
     - 校验通过说明密钥协商成功
   - 作用：完成密钥协商，后续 HTTP 数据用会话密钥对称加密传输
   ***
   **笔试必记要点**
   | 要点         | 内容                                                   |
   | ---------- | ---------------------------------------------------- |
   | **顺序**     | 先 **TCP 三次握手** → 再 **TLS 四次握手**，不要混淆                 |
   | **加密分工**   | 非对称加密只传预主密钥，业务数据用 **对称加密**（兼顾安全和效率）                  |
   | **安全特性对应** | 证书校验 = **身份认证**、密钥加密 = **机密性**、Finished 校验 = **完整性** |
   | **版本注意**   | TLS 1.3 已简化流程，笔试基本只考 **TLS 1.2 四次握手**                |
3. **HTTPS 连接建立完整流程**
   - TCP 三次握手 → TLS 四次握手 → 加密通信
   - 比 HTTP 多了 TLS 握手，所以首次连接更慢
4. **浏览器安全策略**
   - **证书校验**：检查证书是否过期、域名是否匹配、是否被吊销
   - **混合内容**：HTTPS 页面中加载 HTTP 资源会被浏览器拦截或警告

### （三）HTTP 版本演进（笔试热点）

| 特性     | HTTP/1.0        | HTTP/1.1              | HTTP/2    | HTTP/3        |
| ------ | --------------- | --------------------- | --------- | ------------- |
| 连接方式   | 短连接（每次请求新建 TCP） | 持久连接（Keep-Alive，默认开启） | 多路复用      | 基于 QUIC（UDP）  |
| 队头阻塞   | 严重（连接无法复用）      | 存在（连接数限制）             | 解决应用层队头阻塞 | 彻底解决 TCP 队头阻塞 |
| 传输格式   | 文本              | 文本                    | 二进制帧      | 二进制帧          |
| 管道化    | 不支持             | 支持（但响应仍按序）            | 真正的并行     | 真正的并行         |
| 头部压缩   | 无               | 无                     | HPACK     | QPACK         |
| 服务器推送  | 无               | 无                     | 支持        | 支持            |
| Host 头 | 可选              | 必须                    | 必须        | 必须            |
| 底层协议   | TCP             | TCP                   | TCP       | UDP           |

**核心记忆点**：

- **HTTP/1.0**：**短连接**，每次请求都要新建 TCP 连接，性能极差
- **HTTP/1.1**：引入**持久连接**（Keep-Alive），但**连接数有限**导致队头阻塞，前端被迫合并资源
- **HTTP/2**：**多路复用**解决并发瓶颈，可以大胆拆包做代码分割
- **HTTP/3**：改用 **UDP + QUIC**，彻底解决 TCP 层队头阻塞，弱网场景更稳定

### （四）浏览器缓存机制（笔试高频）

1. **缓存分类**
   - **强缓存**：不发请求，直接使用本地缓存
     - `Cache-Control: max-age=3600`（秒，HTTP/1.1）
     - `Expires: Wed, 21 Oct 2025 07:28:00 GMT`（绝对时间，HTTP/1.0）
   - **协商缓存**：发请求询问服务器资源是否变化
     - `ETag`：资源唯一标识（优先级高）
     - `Last-Modified`：资源最后修改时间
2. **缓存优先级流程**
   ```
   请求资源 → 检查强缓存 → 命中？→ 直接使用（200 from cache）
                      ↓ 未命中
              发送请求带协商缓存头 → 服务器返回 304（未修改）或 200（新资源）
   ```
3. **缓存优先级（从高到低）**
   - 内存缓存 > Service Worker 缓存 > HTTP 磁盘缓存 > 网络请求

***

### （五）跨域（CORS）必背要点

1. **同源策略定义**
   - 协议相同 + 域名相同 + 端口相同 = 同源
   - 任一不同即为跨域，浏览器会阻止请求
2. **跨域解决方案（笔试常考）**
   - **CORS**（最常用）：服务器配置 `Access-Control-Allow-Origin` 响应头
   - **JSONP**：利用 `<script>` 标签不受同源限制（仅支持 GET）
   - **代理服务器**：开发环境配置 webpack/vite 代理，生产环境用 Nginx
   - **postMessage**：窗口间通信
   - **WebSocket**：不受同源策略限制
3. **CORS 预检请求（OPTIONS）**
   - 非简单请求（PUT/DELETE/自定义头）会先发送 OPTIONS 预检
   - 服务器返回允许的域名、方法、头部，浏览器才发正式请求

### （六）前端网络优化要点

1. **减少请求数**
   - 雪碧图（CSS Sprites）
   - JS/CSS 合并（HTTP/1.1 时代）
   - 代码分割（HTTP/2 时代）
2. **利用缓存**
   - 静态资源加 hash + 长期强缓存
   - 合理设置 Cache-Control
3. **压缩传输**
   - Gzip / Brotli 压缩
   - 图片 WebP 格式
4. **加载策略**
   - 懒加载（图片、组件）
   - 预加载 `<link rel="preload">`
   - DNS 预解析 `<link rel="dns-prefetch">`
5. **网络层优化**
   - CDN 加速
   - HTTP/2 多路复用
   - Keep-Alive 长连接

## 三、高频易混考点辨析

### 1. GET vs POST（笔试超高频）

| 对比项  | GET               | POST      |
| ---- | ----------------- | --------- |
| 参数位置 | URL（Query String） | Body      |
| 数据大小 | 受 URL 长度限制        | 无限制       |
| 安全性  | 低（参数暴露在 URL）      | 相对较高      |
| 幂等性  | **幂等**（多次请求结果相同）  | **非幂等**   |
| 缓存   | 会被浏览器缓存           | 默认不缓存     |
| 用途   | 获取数据              | 提交数据、创建资源 |

### 2. 301 vs 302（重定向）

- **301 永久重定向**：SEO 权重转移，搜索引擎会更新 URL
- **302 临时重定向**：SEO 权重不转移，临时跳转

### 3. 401 vs 403

- **401 Unauthorized**：未认证（需要登录）
- **403 Forbidden**：已认证但无权限（登录了但没权限）

### 4. 强缓存 vs 协商缓存

| 特性    | 强缓存                          | 协商缓存                 |
| ----- | ---------------------------- | -------------------- |
| 是否发请求 | **不发**                       | **发请求**              |
| 状态码   | 200 (from memory/disk cache) | 304 Not Modified     |
| 控制头   | Cache-Control / Expires      | ETag / Last-Modified |
| 优先级   | 优先检查                         | 强缓存失效后使用             |

### 5. Cookie vs LocalStorage vs SessionStorage

| 特性    | Cookie   | LocalStorage | SessionStorage |
| ----- | -------- | ------------ | -------------- |
| 容量    | 4KB      | 5-10MB       | 5-10MB         |
| 生命周期  | 可设置过期时间  | 永久（需手动清除）    | 页面关闭即清除        |
| 服务端读取 | 自动携带在请求头 | 不能           | 不能             |
| 作用域   | 域名+路径    | 同源窗口共享       | 同一窗口           |

## 四、笔试速记口诀

1. **状态码口诀**：
   - **2开头，都成功**；**3开头，去重定向**
   - **4开头，你错了**；**5开头，我挂了**
2. **GET/POST 口诀**：
   - **GET 幂等查数据，POST 创建非幂等**
   - **GET 参数放 URL，POST 数据藏 Body**
3. **缓存口诀**：
   - **强缓存不发请求，协商缓存问服务器**
   - **Cache-Control 管强缓存，ETag 管协商缓存**
4. **HTTPS 口诀**：
   - **HTTP 明文裸奔，HTTPS 加密穿衣**
   - **TLS 握手四次，加密完整身份验**
5. **跨域口诀**：
   - **协议域名端口同，三者缺一即跨域**
   - **CORS 配响应头，JSONP 仅限 GET**

### 三、笔试必盯坑点

**1. GET/POST 坑点**

- GET **可以**有 Body（但不推荐）
- POST **也可以**幂等（取决于业务实现）
- 标准定义的 GET 是幂等的，但实际开发中要注意

**2. 缓存坑点**

- `Cache-Control: no-cache` 不是不缓存，而是**强制协商缓存**
- `Cache-Control: no-store` 才是**真正不缓存**
- 刷新页面（F5）会跳过强缓存，但会带协商缓存头
- 强制刷新（Ctrl+F5）会跳过所有缓存

**3. HTTPS 坑点**

- HTTPS 不是单独的协议，而是 **HTTP + TLS**
- TLS 握手在 TCP 握手之后，所以 HTTPS 建立连接更慢
- 证书验证失败会导致浏览器显示安全警告

**4. 跨域坑点**

- 跨域是**浏览器**的限制，服务端可以正常收到请求
- CORS 需要**服务端**配置响应头，前端无法单独解决
- 简单请求不会触发预检，非简单请求才会
