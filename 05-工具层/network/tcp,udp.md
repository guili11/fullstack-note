# TCP & UDP 笔试通用背诵笔记（精简版，直接背诵）

## 一、核心属性总对比（表格速记，笔试高频考点）

| 对比维度  | TCP（传输控制协议）                   | UDP（用户数据报协议）             |
| ----- | ----------------------------- | ------------------------ |
| 连接特性  | **面向连接**（通信前必须建立连接）           | **无连接**（无需建立连接，直接发数据）    |
| 可靠性   | **可靠传输**，保证数据完整、有序、不丢失        | **不可靠传输**，不保证送达、有序，丢包不重传 |
| 传输形式  | **面向字节流**                     | **面向报文**                 |
| 核心机制  | 超时重传、确认应答(ACK)、序号重排、流量控制、拥塞控制 | 仅基础校验和，无复杂控制机制           |
| 连接流程  | 建连：三次握手；断连：四次挥手               | 无握手、无挥手，随时收发数据           |
| 端口规则  | 与UDP端口空间相互独立                  | 与TCP端口空间相互独立             |
| 传输延迟  | 延迟偏高（重传、校验、流控带来开销）            | 延迟极低（开销小）                |
| 广播/多播 | 不支持                           | 支持广播、多播                  |
| 适用场景  | 要求**数据绝对可靠**，可接受延迟            | 要求**低延迟**，容忍少量丢包         |

***

## 二、分模块精细化背诵要点

### （一）TCP 必背要点

1. **连接相关**   核心就是 通过两对 syn ack，  让双方，发送方确认能收到接收方的 肯定信息，得知接收方可以接收， 同步序列号+避免重试。
   - 建立连接：**三次握手**
     - 第一次：客户端发送 SYN 包 (seq=x) 到服务端，进入 SYN\_SENT 状态
     - 第二次：服务端收到 SYN 包，回复 SYN+ACK 包 (seq=y, ack=x+1)，进入 SYN\_RECV 状态
     - 第三次：客户端收到 SYN+ACK 包，回复 ACK 包 (ack=y+1)，双方进入 ESTABLISHED 状态，连接建立
   - 断开连接：**四次挥手**（客户端确认和申请分开，因为可能服务端还有数据要发送）
     - 第一次：客户端发送 FIN 包，进入 FIN\_WAIT\_1 状态
     - 第二次：服务端收到 FIN，回复 ACK，进入 CLOSE\_WAIT 状态；客户端收到 ACK 后进入 FIN\_WAIT\_2 状态
     - 第三次：服务端发送完剩余数据后，发送 FIN 包，进入 LAST\_ACK 状态
     - 第四次：客户端收到 FIN，回复 ACK，进入 TIME\_WAIT 状态；服务端收到 ACK 后立即关闭；客户端等待 2MSL 后关闭           
   - 通信双方全程维持连接状态，一方下线会正常断开连接。
2. **可靠传输五大保障（笔试高频多选/判断）**
   - 确认应答（ACK）：接收方收到数据后回传确认包。
   - 超时重传：超时未收到ACK，自动重发丢失数据包。
   - 报文序号：给数据包编号，接收方按序号重排，保证有序。
   - 流量控制：解决**发送方发送太快，接收方缓冲区装不下**的问题。
   - 拥塞控制：解决**整个网络链路拥堵**，主动降低发送速率。
   - 滑动窗口：实现**批量传输**，允许连续发送多个数据包而无需等待每个ACK，提高吞吐量
3. **面向字节流（易错点）**
   - 把应用层数据当成**连续的字节流**，无报文边界。
   - 发送方多次发送的数据，接收方可能合并接收；也可能拆分大数据包。
4. **典型应用**
   HTTP/HTTPS 网页、文件传输、账号登录、支付、邮件等。

### （二）UDP 必背要点

1. **核心特点**
   - 无需建立连接，上手直接发包，通信效率最高。
   - 仅有简单校验和，发现错误直接丢弃报文，**不会重传、不会纠错**。
2. **面向报文（易错点）**
   - 严格保留应用层交付的**原始报文**，**不拆分、不合并、不重组**。
   - 发送多大的报文，接收方就收到多大的报文，报文边界不会改变。
3. **优势与短板**
   - 优势：延迟低、开销小、支持广播/多播。
   - 短板：无法保证数据可靠、有序到达。
4. **典型应用**
   实时语音/视频直播、网络游戏、DNS域名查询。

### （三）端口规则（你之前知识盲区，重点背诵）

1. **核心规则**
   - TCP 和 UDP 是**两套完全独立的端口空间**：同一台机器上，`TCP 80` 和 `UDP 80` 可以同时被不同程序占用，互不冲突。
   - **同协议端口独占**：同一个协议下（如纯TCP），**一个端口同一时刻只能被一个进程监听**，不能多个服务共用同一个TCP监听端口。
2. **笔试常考默认端口**
   - HTTP：TCP 80
   - HTTPS：TCP 443
   - DNS查询：优先 UDP 53；大报文DNS数据使用 TCP 53
   - FTP：TCP 21

## 三、高频易混考点辨析（针对你错题专项突破）

### 1. 流量控制 VS 拥塞控制（极易混淆）

- **流量控制**：点对点问题 → 管**接收方**，防止接收方缓冲区溢出。
- **拥塞控制**：全局网络问题 → 管**整个链路**，防止网络拥堵。

### 2. 面向字节流 VS 面向报文（你错题考点）

- TCP（字节流）：无边界，数据可拆分、可合并。
- UDP（面向报文）：有边界，报文完整收发，不拆不合。

### 3. TCP 可靠传输手段（你错题考点）

✅ 属于可靠机制：确认应答、超时重传、序号重排、流量控制、拥塞控制
❌ 不属于：广播/多播、面向字节流、端口分配

### 4. 丢包场景表现

- 弱网丢包时：TCP 反复重传 → 延迟累积、卡顿；UDP 直接丢包 → 出现杂音、花屏，但延迟不变。

## 四、笔试速记口诀（短时记忆，做题秒选）

1. 连接口诀：**TCP牵手挥手，UDP说走就走**
2. 可靠性口诀：**TCP稳、慢、准；UDP快、飘、野**

## 五、笔试题型与复习策略（应试指导）

### 一、两大核心题型（占比 90% 以上，必拿下）

#### 题型一：TCP 与 UDP 对比辨析题（基础题，题量最多）

所有题目都是围绕**二者核心特性做对比、选正确/错误选项**，固定出题维度：

1. 基础属性：面向连接/无连接、可靠/不可靠
2. 传输形态：TCP面向字节流、UDP面向报文
3. 内置机制：TCP 独有（超时重传、ACK确认、流量控制、拥塞控制）；UDP 仅有简单校验和
4. 能力差异：是否支持广播/多播、传输延迟高低
5. 端口规则：TCP/UDP 端口空间相互独立、同协议端口独占
6. 应用场景：区分哪些业务用 TCP、哪些用 UDP
7. 场景分析：弱网丢包下二者的不同表现

**常见问法**

- 下列说法正确/错误的是？
- 实时直播/文件传输优先使用哪个协议？
- 以下属于 TCP/UDP 特点的是？

***

#### 题型二：TCP 专属流程题（三次握手 + 四次挥手，高频难点、拉分题）

UDP 无连接、无握手挥手，所以这类题**只考 TCP**，细分出题方向：

1. 基础流程：握手/挥手次数、每一步报文标志位（`SYN`/`ACK`/`FIN`）、报文组合
2. 状态流转：连接建立/断开过程中，客户端、服务端对应的 TCP 状态（`SYN_SENT`、`ESTABLISHED`、`FIN_WAIT_1`、`TIME_WAIT` 等）
3. 原理问答（笔试超级高频）
   - 为什么建连要用**三次握手**，不能简化为两次？
   - 为什么断连要用**四次挥手**，不能简化为三次？
   - `TIME_WAIT` 状态的时长（2MSL）、作用是什么？
   - TCP 半关闭的含义（四次挥手的本质）
4. 异常场景：报文丢失、对方异常下线（断电/崩溃）对应的行为、标志位（`RST` 重置）

**常见问法**

- 第二次握手携带什么标志位？
- 主动断连方发送 FIN 后进入什么状态？
- TIME\_WAIT 等待多久、作用不包括哪项？
- 服务端 SYN+ACK 报文丢失，客户端会如何处理？

***

### 二、补充：少量衍生小题（同考点簇，占比约10%）

不属于上面两大主类，但依然是 TCP/UDP 范围，大厂偏难笔试会穿插考查：

1. TCP 可靠传输机制单独考查：ACK、超时重传、序号、滑动窗口各自的作用
2. 知名默认端口：HTTP(TCP80)、HTTPS(TCP443)、DNS(UDP53) 等
3. 冷门标志位：`RST`（异常重置连接）、`PSH`（推送数据）的含义
4. 滑动窗口基础概念：流量控制的实现方式

***

### 三、笔试必盯坑点（结合错题整理）

按照出题概率排序，优先巩固这些易错点：

**1. 对比题坑点**

- 混淆**字节流 / 面向报文**
- 分不清**流量控制（管接收方）** 和 **拥塞控制（管全网链路）**

**2. 流程题坑点（失分重灾区）**

- TCP 各个状态名称与对应阶段
- TIME\_WAIT：时长 2MSL、两大核心作用
- 牢记：`SYN` 只用于建连，`FIN` 只用于断连，二者不会同时出现
- 三次握手不能简化为两次的原因、四次挥手的本质（全双工+半关闭）
- 正常断连用 `FIN`，异常断连用 `RST`

***

### 四、复习&刷题建议（适配笔试）

1. 优先吃透**两大核心题型**，这部分吃透，TCP/UDP 选择题基本满分；
2. 衍生小题不用刷大量新题，把真题里出现过的端口、标志位、滑动窗口结论背熟就行；
3. 刷题顺序：先刷「TCP/UDP对比题」巩固基础，再集中刷「三次握手/四次挥手」攻克难点。
