# HTTPS 是怎么基于 HTTP 实现的？

HTTPS 就是在明文传输的 HTTP 协议与底层 TCP 传输层之间，额外增加了一层 **TLS 安全协议**：

## 连接建立流程

1. **TCP 连接**：客户端和服务器先完成 TCP 三次握手
2. **TLS 握手**：执行 TLS 握手流程
   - 客户端校验服务器的数字证书，完成身份认证
   - 防止访问假冒站点
3. **密钥协商**：双方借助非对称加密算法，协商出临时的对称会话密钥

## 数据传输阶段

- **加密传输**：后续所有 HTTP 请求和响应数据，都会用会话密钥加密后传输
  - 避免数据被窃听
- **完整性校验**：通信数据附带哈希摘要
  - 接收端通过比对摘要判断数据是否被篡改

## 总结

依靠 TLS 层补足了安全能力，让原本裸奔的 HTTP 变成了安全可信的 HTTPS。

## 附录：对称加密 vs 非对称加密

### 对称加密

**原理**：加密和解密用**同一把密钥**

```
明文 + 密钥 → 加密 → 密文
密文 + 密钥 → 解密 → 明文
```

**特点**：速度快，但密钥分发困难（如何把密钥安全给对方？）

***

### 非对称加密

**原理**：密钥成对出现，**公钥加密，私钥解密**

```
明文 + 公钥 → 加密 → 密文
密文 + 私钥 → 解密 → 明文
```

**核心特性**：

- **公钥公开**：可以发给任何人，不怕被截获
- **私钥保密**：只有持有者知道，绝不外泄
- **单向性**：公钥加密的数据，只有对应私钥能解开

**为什么叫"非对称"**：加密和解密用的不是同一把钥匙，而是**一对配套的钥匙**

***

### 对比表格

| 特性       | 对称加密            | 非对称加密                       |
| -------- | --------------- | --------------------------- |
| **密钥**   | 双方用**同一把密钥**    | 密钥成对：**公钥**（公开）+ **私钥**（保密） |
| **速度**   | ⚡ **快**（适合大数据量） | 🐢 **慢**（计算复杂）              |
| **安全性**  | 密钥分发困难          | 公钥随便传，私钥不外泄                 |
| **典型算法** | AES、DES         | RSA、ECC                     |
| **用途**   | 加密实际传输的数据       | 加密密钥、数字签名                   |

### 一句话记忆

- **对称加密**：一把钥匙开一把锁，快但钥匙难传
- **非对称加密**：公钥锁、私钥开，慢但安全

### TLS 中的应用

```
客户端要发预主密钥给服务端：

预主密钥 + 服务端公钥 → 加密 → 密文
                              ↓ 网络传输（被截获也不怕，没有私钥解不开）
密文 + 服务端私钥 → 解密 → 预主密钥
         ↑
    只有服务端有私钥，所以只有服务端能解密
```

临时会话密钥是如何生成的呢？（对称加密）

双方随机数+客户端 生成的随机  预主密钥    

注意：公钥是用于跟私钥搭配 保护这个预主密钥传过去的
