前言 介绍 程序 进程 线程 
程序：存储在 硬盘上的静态可执行文件  
进程：程序运行的一个实例，内存资源分配的最小单位
线程：进程中的一个执行单元，可以有多个，cpu时间片分配的最小单位

解释：程序本身是静态的，需要我们提供 运行环境（内存）以及 执行者（cpu），才能运行，
运行环境：临时提供的一些服务，例如  go语言提供的语言运行环境，加载到内存中，才能 被使用去解释go语言， 总结：需要分配内存
执行者：程序到最根本就是一些指令，例如io指令，计算指令 等等，  总结：需要分配到cpu时间片
补充：指令中有慢指令，例如io指令，cpu只需要执行要求io设备命令（很快），但是io设备执行（很慢），最终拿到io结果，原本需要io操作的程序，才接着往下，这段时间内，cpu就空闲了，俗称cpu空转，  
所以cpu时间片是可以分配的，当原本的线程因为io等操作等待的时候，cpu去执行其他线程

其实本质就是 

所以 设计了两个概念来分配 进程 和 线程，
一个分配内存，一个分配cpu时间片，

现在有那么多空闲时间片，我们得分配，所以就有了多线程


序章1 并发编程
并发：是指多个线程任务在同一个CPU上快速地轮换执行，由于切换的速度非常快，给人的感觉就是这些线程任务是在同时进行的，但其实并发只是一种逻辑上的同时进行； 
并行：是指多个线程任务在不同CPU上同时进行，是真正意义上的同时执行。

并发是一种效果，为了实现并发（效果），我们就得需要异步（手段）。

序章2 一个程序内的 同步和异步  js主要提及

介绍：
cpu同步：单执行流串行执行，遇到 IO 会阻塞挂起自身；单线程同步阻塞时，线程停下等待，该执行流停滞
cpu异步：发起 IO / 耗时操作不阻塞当前执行流，执行流继续往后走；底层依靠多线程 / 协程调度，阻塞线程让出 CPU，让其他任务运行，从而提升 CPU 利用率

我们当然希望实现cpu利用率，进而，我们就得实现异步 

操作系统的 底层能力 多线程  就是实现异步的核心机制

序章3 那么 异步编程指的是什么呢？
其实就是上述异步的代码实现：只不过 不同语言有不同的实现，例如go的实现就是 goruntine，python的实现就是 asyncio，js的实现就是 async/await 等等   底层基础都是多线程哦

注意：上述是从cpu利用率角度考虑的问题， 那么那个等待io结束后续代码怎么继续执行？
但是在 某段代码内部 ，io操作后续的指令得等待io操作完成， 就叫做程序内的等待了。（阻塞等待嘛， **程序等待**，cpu可不等）
等待过程，其实就是线程挂起嘛，等到io操作完了，再去请求cpu时间片，继续执行。

序章4 同步方法和异步方法：注意区分cpu层面的同步和异步
同步方法是指调用这个方法后，调用方必须等到这个方法执行完成之后才能继续往下执行。  **调用方处理结果**
异步方法是指调用这个方法后会立马返回，调用方能立马往下继续执行。
被调用的异步方法由另外的线程 / 协程执行；
如果有返回值，不会通知调用方，而是通过指定方式交给 结果处理者处理。  **调用方发起，处理者处理结果**

本质其实就是业务需求，看方法的结果后续是否自己处理，还是交给处理者处理。 

序章5 go语言并发是如何实现的？
go：轻量协程 Goroutine + GMP 调度模型
协程 Goroutine：
  系统线程（MB 级）：创建 / 切换成本极高；
  Goroutine（KB 级）：一个 Go 程序轻松开启上万、几十万个协程，无压力。
  
GMP 调度模型
G（Goroutine）：Go **协程**，承载具体业务执行任务，轻量级执行单元，数量可海量创建
M（Machine）：操作系统**原生内核线程**，是唯一能被 CPU 直接调度执行的单元
P（Processor）：逻辑处理器，调度管理核心，负责衔接 G 与 M，**维护协程运行队列**
p中维护一个g协程运行队列，轮到的时候 交给m执行，g遇到io的时候挂起，轮到队列中后面的g运行，io结束后 重新回到队列，

终章  并发安全？

一、并发安全定义
在多个独立执行单元（线程 / 轻量执行单元）同时推进任务的并发场景下，多个执行单元访问、修改公共共享资源时，程序最终运行结果与预设逻辑结果完全一致，不会出现数据错乱、逻辑异常、程序卡死等问题，该状态即为并发安全；反之执行结果不可控、出现异常，就是并发不安全。
二、并发不安全产生的核心根源
存在共享资源
多个执行单元共同使用同一份公共资源，如公共数据、内存变量、文件资源、硬件资源等，是引发冲突的前提。
执行顺序不可控
CPU 采用抢占式时间片调度机制，执行单元的运行、暂停、切换时机由系统调度决定，人为无法固定执行先后顺序。
操作非原子性
对共享资源的一次业务操作，会被拆分为多条底层指令，调度切换可发生在任意指令间隙，打断完整操作流程。
三、常见并发安全问题（纯理论）
竞态条件（数据竞争）
多个执行单元同时读写同一共享数据，读写操作相互穿插打乱，破坏数据完整性，最终计算结果偏离预期，是最普遍的并发问题。
指令重排异常
硬件处理器、编译层为提升运行效率，会自主调整指令执行顺序；单执行单元无影响，多并发场景下会打乱业务逻辑顺序，引发逻辑错误。
死锁
多个执行单元互相持有对方所需的共享资源，同时互相等待对方释放资源，所有执行单元全部阻塞停滞，程序彻底卡死无法继续运行。
活锁
执行单元持续主动放弃已抢占的资源，反复重试争抢资源，始终无法正常完成业务执行，无限循环空耗系统资源。
线程饥饿
部分优先级低的执行单元，长期无法抢占到所需共享资源，持续处于等待状态，永远无法完成自身任务。
四、通用并发安全解决核心思想
1. 互斥访问思想（最常用）
核心规则：同一时刻，仅允许一个执行单元访问修改共享资源
将操作共享资源的代码划定为临界区，对临界区做访问限制，强制所有执行单元串行进入执行，杜绝并发争抢，从行为上避免数据冲突。
2. 执行同步思想
人为约束多个执行单元的执行先后顺序，让存在业务依赖的任务按照既定顺序依次执行，依靠执行时序规避乱序带来的逻辑错误。
3. 消除共享思想（最优治本方案）
从根源切断冲突条件，尽量拆分资源，让每一个执行单元使用私有独立资源，减少乃至取消公共共享资源；无资源争抢，自然不存在并发安全问题。
4. 资源有序分配思想（专治死锁）
统一制定所有共享资源的获取顺序，所有执行单元必须严格按照相同顺序申请、占用资源，彻底破除死锁形成的循环等待条件。
