Lifecycle Line (服务生命周期)     不追求理解透彻，要知道要做什么事情就可

## 启动
├─ Phase A: Pre-Run (环境就绪)
│  ├─ ⭐ 环境变量加载 (Env)
│  │  ├─ 任务：定义服务运行的基础身份标识（实例 ID、环境、Region）
│  │  └─ 方案：os.Getenv / viper / K8s Downward API
│  ├─ ⭐ 配置源读取 (Provider)
│  │  ├─ 任务：从统一的配置中心或本地文件获取业务配置
│  │  └─ 方案：Nacos SDK / Etcd Watch / 本地 yaml / viper 多源合并
│  ├─ ⭐ 配置校验 (Validator)
│  │  ├─ 任务：启动前拦截缺失或错误的配置项，防止带着错误配置运行
│  │  └─ 方案：go-playground/validator / json-schema / 自定义 validate
│  └─ 🚀 密钥管理 (Secret)
│     ├─ 任务：数据库密码、API Key 等敏感信息不写死在配置文件或代码中
│     └─ 方案：Vault / KMS / Kubernetes Secret 环境变量注入
├─ Phase B: Initialization (资源预热)
│  ├─ ⭐ 结构化日志 (Logger)
│  │  ├─ 任务：初始化日志引擎，使所有模块输出统一格式、带 TraceID 的日志
│  │  └─ 方案：zap / logrus / zerolog + 日志轮转 lumberjack
│  ├─ ⭐ 存储池初始化 (Pools)
│  │  ├─ 任务：建立与 MySQL、Redis 等中间件的连接池，并预热连接
│  │  └─ 方案：GORM / sqlx / go-redis 连接池配置 + 启动后 ping
│  ├─ 🚀 观测性注入 (Telemetry)
│  │  ├─ 任务：初始化指标采集与链路追踪，使服务可观测
│  │  └─ 方案：Prometheus Client / OpenTelemetry + Jaeger 导出
│  └─ 🚀 依赖检查 (Dependency Check)
│     ├─ 任务：启动前确认下游服务、数据库、消息队列等是否可达
│     └─ 方案：TCP 拨测 / ping / 健康接口探测
├─ Phase C: Exposure (服务暴露)
│  ├─ ⭐ 路由注册 (Registry)
│  │  ├─ 任务：将业务 API 定义挂载到具体的协议服务器上
│  │  └─ 方案：Gin / Echo / gRPC 路由注册 + 中间件链
│  ├─ ⭐ 端口绑定 (Listen)
│  │  ├─ 任务：在操作系统层面开启端口监听，接收外部请求
│  │  └─ 方案：net.Listen / 指定 :port / 多协议多端口
│  └─ 🚀 服务发现注册 (Discovery)
│     ├─ 任务：启动成功后向注册中心发送"已在线"信号，让调用方发现本服务
│     └─ 方案：Nacos / Etcd / Consul / Kubernetes Service

## 运行
├─ Phase D: Runtime (运行维护)
│  ├─ ⭐ 健康检查 (Health Check)
│  │  ├─ 任务：提供 Liveness（存活）与 Readiness（就绪）接口供 K8s 探测
│  │  └─ 方案：/healthz + /readyz 端点 + 依赖状态聚合
│  ├─ 🚀 信号监听 (Signal)
│  │  ├─ 任务：捕捉 SIGTERM/SIGINT 等系统信号，触发优雅退出流程
│  │  └─ 方案：signal.Notify + channel 监听
│  └─ 🚀 后台任务管控 (Background)
│     ├─ 任务：异步任务（定时任务、消费队列）在独立 Context 下运行，受主程生命周期控制
│     └─ 方案：errgroup / goroutine + select channel

## 退出
└─ Phase E: Shutdown (优雅退出)
   ├─ ⭐ 拒绝新请求 (Drain)
   │  ├─ 任务：收到退出信号后先关闭 Listener，停止接收新流量
   │  └─ 方案：http.Server.Shutdown / 自定义 graceful shutdown
   ├─ ⭐ 上下文撤销 (Cancel)
   │  ├─ 任务：通过 Context 广播取消信号，通知所有子协程开始收尾
   │  └─ 方案：context.WithCancel / cancel()
   ├─ 🚀 资源释放 (Cleanup)
   │  ├─ 任务：按启动逆序关闭数据库连接池、文件句柄等资源
   │  └─ 方案：defer / close / 逆序调用 close 方法
   └─ 🚀 优雅时延 (Graceful Period)
      ├─ 任务：预留 5-10s 等待正在处理的内存任务完成，再物理退出
      └─ 方案：time.Sleep / sync.WaitGroup / 等待 context deadline
